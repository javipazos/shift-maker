## Project

Shift Maker — local web app for generating monthly rotating shift schedules for small teams (2-6 people). Full spec in `PROMPT_SHIFT_SCHEDULER_2.md`.

## Quick Start

```bash
./setup.sh
```

This single command installs dependencies, runs tests, and starts both servers. The browser opens automatically at http://localhost:5173.

Prerequisites: `uv` (Python) and `node` (>=18).

## Manual Setup

```bash
# 1. Backend
cd server
uv venv
uv pip install -e ".[dev]"
.venv/bin/pytest -v                                    # run tests
.venv/bin/uvicorn app.main:app --reload --port 8000    # start API

# 2. Frontend (separate terminal)
cd client
npm install
npm run dev                                            # starts at :5173, proxies /api → :8000
```

API docs at http://localhost:8000/docs (auto-generated by FastAPI).

## Stack

- **Frontend**: React + Vite + CSS (no Tailwind, no CSS frameworks)
- **Backend**: Python + FastAPI
- **Solver**: Google OR-Tools CP-SAT (native Python import)
- **DB**: SQLite via Python stdlib sqlite3 (no ORM)
- **Export**: openpyxl (xlsx)
- **Testing**: pytest (backend)

## Commands

```bash
# Tests
cd server
.venv/bin/pytest -v                           # all 127 tests
.venv/bin/pytest tests/test_rules/ -v         # rule tests only
.venv/bin/pytest tests/test_solver.py -v      # solver tests only
.venv/bin/pytest tests/test_routes/ -v        # API route tests

# Makefile shortcuts (from root)
make test          # all backend tests
make dev-server    # FastAPI dev server
make dev-client    # Vite dev server
make install       # install all dependencies
```

## Architecture

- `server/app/` — FastAPI application
  - `db.py` — SQLite schema, connection, seed data (4 employees, 3 shifts, 14 rules)
  - `models.py` — Pydantic request/response models
  - `deps.py` — Dependency injection (get_db)
  - `routes/` — API endpoints (employees, shift_types, absences, rules, schedules, export)
  - `rules/` — Rule engine: 14 rules across 4 categories (rest, coverage, equity, limits)
  - `solver/` — OR-Tools CP-SAT model builder + solver orchestration
  - `services/` — validator (runs rules), exporter (xlsx via openpyxl)
- `client/src/` — React frontend
  - `components/` — UI components (layout, schedule, config, absences, validation, summary)
  - `hooks/` — useSchedule (data + editing), useValidation (rule checking)
  - `styles/` — CSS with custom properties (variables.css)
  - `api/` — types + fetch wrappers

## Key Design Decisions

- All rule logic lives only in Python — no duplication in TypeScript. Frontend calls POST /api/.../validate.
- Rules have two facets: `validate()` for checking schedules, `add_constraints()` for CP-SAT solver.
- Violations classified as correctable vs structural (mathematically impossible with available staff).
- Nothing blocks schedule generation — solver always produces a result, violations inform the human.
- SQLite with `check_same_thread=False` for FastAPI's thread pool.
- Vite proxies `/api` requests to FastAPI at port 8000.
